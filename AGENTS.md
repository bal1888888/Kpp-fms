# Aturan Kerja KPP-FMS

- Kerjakan hanya pada branch kerja; jangan melakukan perubahan langsung di `main`.
- Buat setiap perubahan sekecil dan sefokus mungkin.
- Jangan commit, push, merge, membuat Pull Request, atau deploy tanpa persetujuan eksplisit pengguna/Tech Lead.
- Jangan membaca file di luar workspace Kpp-fms dan jangan memakai jaringan tanpa persetujuan.
- Jangan membocorkan secret, token, password, atau Supabase key dalam kode, dokumentasi, log, maupun output.
- Jangan mengubah database, RLS, role, atau alur operasional tanpa persetujuan eksplisit.
- Pertahankan semua perubahan milik pengguna dan hentikan pekerjaan jika ada perubahan tak dikenal atau konflik.
- Sebelum implementasi, laporkan rencana kecil dan file yang akan disentuh.
- Setelah implementasi, laporkan file yang berubah, hasil pemeriksaan/test, `git diff --check`, dan `git status`.
- Codex bertugas sebagai implementer dan reviewer teknis; keputusan alur bisnis, role, database, dan arsitektur tetap memerlukan persetujuan pengguna/Tech Lead.
- Selalu periksa `git status` dan `git diff` sebelum serta sesudah perubahan.
- Jangan menjalankan tindakan destruktif.
- Pertahankan kompatibilitas GitHub Pages serta tampilan dan fungsi pada PC maupun HP.
